# Conflict resolution

Follow instruction priority first. Apply explicit current user authorization within higher-priority boundaries. Then follow repository authority rules and applicable scoped AGENTS.md policies.

Do not invent a universal document ranking where the repository defines its own. Approved requirements govern intended behavior; source governs observed implementation; immutable run records govern measured outcomes. A newer summary does not rewrite historical evidence, and implementation does not prove owner approval.

For contradictions, identify both claims, dates, versions, scopes and evidence. Resolve only when an explicit authority or factual record supports the resolution. Otherwise mark the conflict and continue independent work; ask only when an unresolved decision blocks the authorized task. Do not rewrite requirements or protected material to make a validator pass.

Preserve user edits. Do not reset, clean, force-push, or overwrite unrelated work. If standard paths conflict with a protected or legacy boundary, use the approved documentation namespace or equivalent-role mapping.
