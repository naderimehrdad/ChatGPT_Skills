# Documentation standard

## Seven mandatory documents

Paths below are relative to the approved documentation root, which may differ from the Git root.

| Document | Responsibility |
| --- | --- |
| README.md | Purpose, navigation, prerequisites and verified setup instructions |
| AGENTS.md | Working rules, boundaries, conditional policies and commands |
| SOURCE_OF_TRUTH.md | Approved requirements, authority, conflicts and unknowns |
| CHANGELOG.md | Material changes and dated historical checkpoints |
| docs/ARCHITECTURE.md | Components, interfaces, dependencies and data flow |
| docs/CURRENT_STATE.md | Current status, blockers, version identities and next work |
| docs/TESTING.md | Verification procedures, observed results and limitations |

These seven roles are the reconstructed edition's explicit convention, not a claim that the missing original specified these exact filenames. Prefer established repository equivalents; record the mapping when necessary. Do not create duplicates just to satisfy the script's default names.

Select the documentation root from explicit instructions. For XAU_MomentumProfit, existing policy designates our-development/ and protects legacy/. Do not hard-code these names into unrelated projects.

Separate approved requirements from implementation observations, measured outcomes, proposals and unknowns. Link to authoritative records rather than duplicating volatile facts. Identify evidence by version, configuration, run date and artifact where available. Keep archived claims dated; state which current record supersedes them.

Read conditional policies relevant to the task: version registries, research plans, data dictionaries, security rules, release procedures, acceptance criteria and frozen-artifact manifests. Do not import project-specific trading rules into this general skill.
