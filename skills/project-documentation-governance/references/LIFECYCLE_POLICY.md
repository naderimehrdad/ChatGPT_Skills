# Lifecycle policy

## Before work
Discover applicable instructions and documentation roots first. Inspect Git status without resetting, stashing or cleaning user edits. Read seven mandatory roles and relevant conditional references before source changes, analysis, or review conclusions. If access or documents are missing, state the specific gap and continue only with work supported by available evidence.

Identify the task boundary, approved requirements, protected files, active versions, and verification procedures. Never infer owner approval from inherited code or good experimental results.

## During work
Keep changes scoped to the request. Preserve protected originals, evidence, frozen versions and unrelated edits. Record commands and outcomes as observed, distinguishing failed, skipped and blocked work. Never silently change requirements to match implementation.

## Before response
Revisit documents affected by actual changes. Update architecture for structural changes, testing for verification changes/results, current state for status changes, source of truth only for authorized requirements, and changelog for material changes. Do not touch all seven merely to record compliance.

Inspect final status/diff and local links. Run the bundled static validator and appropriate project checks if possible. Explain any blocker or tool limitation. Do not modify files for a read-only request solely to satisfy documentation bookkeeping.

## Legacy bootstrap
Bootstrap is a reversible project mutation, permitted when documentation creation is within the authorized task. Preview with --dry-run then use --apply only after reviewing paths against protected boundaries. Scripts never establish project facts. Complete generated placeholders from observed sources and mark unknowns honestly.

Never auto-commit, push, deploy, promote experimental work, or operate external systems. Carry out such actions only within explicit user authorization and higher-priority boundaries.
